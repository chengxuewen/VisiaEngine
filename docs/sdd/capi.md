# visiaengine-capi behavioral contract (CAPI-NN)

C ABI plane clauses. **The canonical bit layouts and encoding rules live in this document (the C header is not exposed [FFI-R:CS-R1])**.

## CAPI-01: handle encoding and generation (slot base 1)
Engine handle = `u64 (slot<<32 | generation)`; **slots are allocated from 1, slot 0 is never occupied** (0 = the dedicated failure/invalid sentinel); destroy recycles the slot (**re-entry of a released handle, including destroy itself, is always -1 — a double destroy is a host-bug signal, not swallowed**), slot reuse advances the generation (stale = an old handle walks in -> `VE_ERR_ARG`); an out-of-table slot (foreign) is likewise -1. On every ve-prefixed entry, argument validation precedes state-machine validation. Entity handles have the same shape but a **different space** (the engine-side slot base-1 bias does not apply to entities: slot0gen0=0 is legal; the miss/out-of-range sentinel = `UINT64_MAX`, and the asymmetry with the engine-side 0 sentinel is an intentional division of labor). abi_version = `(major<<16)|minor`, the host validation plane is always `>>16==1` (the machine exit of the promise to only increment within MAJOR); 0x00010000 initial version, 2026-09-15 the three attribute entries (CAPI-10..12) appended -> minor=1.

## CAPI-02: panic barrier (VE_ERR_PANIC does not spill)
All 17 extern entry bodies go through the single `capi_guard` macro (= catch_unwind(AssertUnwindSafe) + TLS diagnostic write + return -4); grep gate: line-start count of `cfg_attr(not(target_arch = "wasm32"), unsafe(no_mangle))` == 17 (v1.3 shape; 2026-09-15 attribute-plane revision 14->17) and zero hits for `pub unsafe extern` signatures (safe signature + internal validation, [FFI-R:FC-5]). After the barrier, subsequent entries with the same handle are unpolluted.

## CAPI-03: thread affinity and error-string protocol
create records the owner ThreadId; every entry outside the **exception set = {abi_version, last_error}** called from a non-owner -> `VE_ERR_STATE` (destroy across threads **does not destroy**) and records a diagnostic containing "thread" in the calling thread's TLS. Error-string protocol: `last_error(ve)` reads the **calling thread's TLS**, thread-bound, **valid until that thread's next error write**; **only the return-value <0 branches may write TLS — any entry returning 0/positive (including destroy's idempotent 0 and on_input's unconsumed 0) must not touch it** (SDL warning plane: strings are forbidden as branch predicates).

## CAPI-06: attach and window lifecycle (I3 implemented)
`attach(ve, win, display, kind)`: kind 0 = x11 (**display mandatory** — Xlib cannot construct a surface without a display) 1 = win32 (display slot = hinstance, 0 = automatic) 2 = appkit; illegal kind / win=0 / empty mandatory slot -> `VE_ERR_ARG`. **Atomicity**: surface-construction/configuration failure preserves the original headless target (no half-way surface switch, errors go -2 + last_error). **Host obligation**: the window and display must stay alive until swapchain destruction (destroy releases immediately; handles persisted across restarts are rejected by the CAPI-01 generation gate). resize = automatic reconfigure next frame; Outdated/Lost digested within the frame; Timeout/Occluded = skip the frame without counting an error (the wgpu counterpart of Filament beginFrame semantics, D8 trigger one honored at last). Pipelines are built lazily per surface caps format (Rgba8Unorm preferred, Bgra* legal — X11 surface formats are diverse, hammered home by the I3 smoke).

## CAPI-05: input mapping and error attribution (front segment, I1 effective subset)
`VeInput.struct_size` too small -> `VE_ERR_ARG` (the -1 entry-argument family; -5 is reserved for buffer/dimension runtime magnitudes — attribution table). kind accounting: PTR_DOWN consumed = 1, subsequent MOVE = orbit consumed = 1, MOVE without a press = 0 (not this engine's event, not consumed), WHEEL = zoom multiplicative (perspective/orthographic shared [E3D:B6]), unregistered kind no-op = 0. Input -> camera = an engine policy, not event pass-through.

## CAPI-04: headless image-output byte chain
The full chain `create_headless -> load_* -> render -> readback` goes through the C ABI: load success = 0 and entity_count grows, render = 0, readback buffer too small -> -5 / null pointer -> -1, readback pixels not background. viewport(w,h) 0 dimension -> the -5 family (w==0 attributed to the -5 magnitude account, attach kind out of range attributed to the -1 argument account). Pick-hit handles ∈ {entity_at(i)} (generation-stable), and the loaded parts' world geometry comes from the same source (REND-23/24 reuse). **B2 domain extension**: the pick-hit domain includes point-cloud entities (products of add_points/load_pcl; mesh preferred, point cloud as the mesh-miss fallback, REND-38/39) — the old "pick domain is mesh-only" wording is abolished as of this clause's revision; the `entity_set_visible` domain synchronously includes point clouds (two-sided render/pick filtering, enumeration domain unchanged).

## CAPI-09: two-sided mirror consistency (web/C constant identity, batch 7 J2′)
The js glue plane (visiaengine-wasm crate)'s `abiVersion` + 11 constant getters are item-for-item equivalent to the capi C ABI constants; `pick/entityAt` are `bigint` on the .d.ts compilation plane (u64 ≡ BigInt [FFI-R:BS-6/7]). The Rust side references the same `pub const` source = identity by construction (no runtime assertion); the cross-language plane is machine-reconciled by `scripts/web-mirror.mjs` (node loads the pkg-node product: 12-item value table + d.ts bigint compile assertion + artifact existence), execution channel = the `web-check` task (build->test, `#[ignore]` explicit chain T2 — no artifact means red, false green forbidden).

## CAPI-10: host attribute reads (entity-keyed three types, missing != zero value)
`attr_f64/attr_str/attr_bool(entity_bits, key)`: entity = the u64 encoding from pick/entity_at, **the key carries generation = ABA-immune** (an old-generation handle never collides with a new-generation row). The four missing paths (no row / no column / wrong type / empty cell) uniformly mean "no value": `Option::None` at the engine layer, the FFI layer returns 0 and writes nothing to out — **missing != zero value** (the host projection of CORE-11/12). The pick surface = mesh parts: Strokes/Markers parts currently carry no entity (pure line/point features are not pickable, the `entity_at` index still reaches their attribute rows) — hosts must not model with a pick-only mindset.

## CAPI-11: attr_str buffer contract
Engine layer `Option<&str>` (borrows the engine); FFI layer writes NUL-terminated into `buf[cap]`: hit = return 1; cap insufficient = `VE_ERR_SIZE`(-5) with **zero partial write and no length-probe submode** (buf=NULL is not special-cased = ruling C-2); null buf/key/out = `VE_ERR_ARG`; host conventional size 256B (demo/documentation plane). The error-string TLS discipline inherits CAPI-03 (only <0 branches may write).

## CAPI-12: attribute retention and additive-reload rows
`load_geojson*` on success moves the `GeoDocument` into the retention plane (`geo_docs` append, isomorphic with the additive semantics of items); entity -> (load ordinal, feature row) back-marked at mount time, row = GEO-17 flatten index; **mount failure = zero publication** (doc not retained, back-marks not inserted, mid-way spawns follow the current orphan semantics). Reload isolation: old entity reads neither drift nor scramble, cross-doc column spaces are independent.

## CAPI-13: entity visibility (render/pick filtering, enumeration domain unchanged)
`entity_set_visible(ve, entity_bits, visible)`: visible = strictly 0/1 (any other value = VE_ERR_ARG); unknown configuration (outside the enumeration domain / old generation) = VE_ERR_ARG; success = 0, repeated same-value sets are idempotent = 0. The hiding semantics, three contracts: **render-command exclusion, pick miss, attribute reads and the entity_count/entity_at enumeration domain unchanged** (host layer toggles depend on index stability; the old-handle hit surface of a hidden part = MISS). Attachments without an entity bit-configuration, such as the line/point expansion tables, are outside this entry's jurisdiction (CAPI-10 domain split carries over).

## CAPI-14: visibility query
`entity_visible(ve, entity_bits) -> int32`: visible = 1, hidden = 0, unknown configuration = -1 (the encoding carries generation = ABA-immune, same domain and lineage as the CAPI-13 setter; the bit-configuration 0 is legal and queryable — never judge existence by value, existence = this entry's/enumeration domain's receipt).

## CAPI-15: procedural mesh add (VeMeshDescC value struct, copied at call time)
`add_mesh(ve, *const VeMeshDescC) -> uint64`: first field struct_size (the VeInput-family forward gate, too small = rejected -> returns 0 and writes last_error); positions/normals (may be NULL = the engine synthesizes +Z, same source as the Flat family; length mismatch = degenerate rejection) / indices / base_color[4] / origin[3] are **read and copied at call time**, after return the host may free legitimately (isomorphic to load_* bytes). Degenerate input (empty positions / empty indices / out-of-range indices / normals length inconsistent with positions) = return 0 (0 is not a normally valid handle), no partial state committed. Return-code regime (same lineage as the attr family): 0 = success writing *out_entity; degenerate/NULL/struct_size gate/bad out = -1 with **zero partial write to out**. The success configuration **may be 0** (slot0gen0 is legal = CAPI-01's intentional division, hosts must not judge validity by 0 — the existence predicate = enumeration domain / pick exit); enumeration domain +1 immediately, render effective immediately, no attribute row (attr reads = the CAPI-10 missing path).

## CAPI-16: entity removal (generation re-entry, double-destroy same lineage)
`remove_entity(ve, entity_bits) -> int32`: success = 0 — removed from items, attribute back-mark table cleaned, visibility table cleaned, core `despawn` advances the slot generation +1; unknown configuration / re-entry with an old handle = VE_ERR_ARG. ABA immunity made explicit: delete -> add again at the same slot -> **the old handle stays dead** (the new entity's new configuration does not collide). The `entity_at` index domain compacts and reorders: after removal the host must re-enumerate (this clause's explicit warning: index stability is not promised, only visibility is — the CAPI-13 divide).

## CAPI-17: event push entry (set_event_callback)
`visiaengine_set_event_callback(ve, cb, user)`: cb = `void(*)(void* user, uint32_t event, uint64_t a, uint64_t b)`; cb=NULL detaches (re-registration = replacement, not stacking). Event domain: `VE_EVT_LOAD_PROGRESS=1` (fired per element inside the load_gltf/load_geojson loop body, a=done b=total, monotonic with terminal state done==total==entity count); `VE_EVT_LOAD_ERROR=2` (fired at the load-failure exit at the same moment as the return value, a=error code b=0). Trigger thread = calling thread (synchronous semantics); once the async asset pipeline lands the trigger thread changes to the loader thread, event ids/order unchanged (forward-compatibility declaration). Re-entering visiaengine_* inside the callback = undefined behavior (forbidden); panic/handle gates same as the CAPI-03 family.

## CAPI-18: point-cloud pass-through load (add_points)
`visiaengine_add_points(ve, const VePointsDesc*, uint64_t* out_entity) -> int32`: raw-array pass-through (reuses the engine-internal create_points -> DrawPoints route, zero change to the render IR). Value-domain division table (C15, zero bit collision with existing rows of CAPI-01/15): return code 0 = the sole success form, non-0 = the existing VE_ERR_* spectrum; out_entity **valid only on success**, the entity configuration 0 is legal and must not be used as a failure sentinel (CAPI-01 division); the struct_size forward gate follows CAPI-15 (smaller than required = rejected); count=0 / NULL marks / degenerate = **zero commit** + VE_ERR_ARG (same lineage as CAPI-15). Domain semantics: VePointMark{pos f32×3 (host-frame local coordinates, origin=[0,0,0]), radius_px screen pixels (REND-30), color sRGB×3 (CORE-16 host plane)}; **non-finite coordinates are accepted as-is** — this entry is the host's responsibility, the four-way dirty-data classification lives on the load side (IO-*, the division is stated in writing); this entry sets no point cap (the sole point-count guard is on the load side). Cloud = single entity, single DrawPoints (consensus 5); the pick domain does not include this entry's products (the established CAPI-04 mesh-only account, not rewritten by this clause).

## CAPI-19: point-cloud file load (load_pcl)
`visiaengine_load_pcl(ve, path, policy, uint64_t* out_entity, VePclReport* out_report) -> int32`: policy = VE_PCL_FASTFAIL(0) / VE_PCL_LENIENT(1), out of range = VE_ERR_ARG; both outs mandatory non-null (NULL = ARG, the single success write-point, zero partial write on failure — same lineage as the attr_str discipline). The capacity gate is IO-05 (Err -> VE_ERR_IO + error string, over-cap is not half-accepted). Nonexistent path/parse failure = VE_ERR_IO; handle gates are the established CAPI-03.

## CAPI-20: cross-section clipping, two entries (B2)
`visiaengine_set_clips(ve, const VeClipPlane *planes, size_t n)` / `visiaengine_get_clips(ve, VeClipPlane *buf, size_t cap)`. `VeClipPlane{nx,ny,nz,d}` = world coefficients, 32B Pod (the normal points to **the kept side**, predicate `dot(n,P)+d ≥ 0`, on the plane = kept). **Value-domain table [C15]**: `n∈[0,4]` (MAX same source as REND-32), **n=0 = the sole clearing form** (planes NULL + 0 legal); `NULL∧n>0` -> -1; `n>4` -> -1 (**bounds check precedes dereference**, zero out-of-range reads); zero normal / non-finite -> -1 + error string (same-source gate as ClipSetup::new, no clamping, no swallowing). Normalization is done engine-side: read-back is always the unit form ((0,2,0,2) -> (0,1,0,1), w divided in sync). get **returns ≥0 = current plane count** (<0 is the dedicated error spectrum, the return value serves no dual duty); buf NULL = count only; `cap < plane count` truncated write = write min, return the true count (n=3,cap=2 -> return 3, write 2). Owner-thread gate = same lineage as the visibility entries; the exception set takes none. Behavior plane: render pipeline fs discard (REND-32 conversion law; WGPU-21/22/23 include the caster/expansion families in the same clip) + **pick hit-point keeps predicate negative side -> excluded from the retry loop** (whatever remains visible after cutting must be pickable; orthogonally stacked with the hidden filter). The wasm mirror = setClips(flat 4n)/getClips -> Float64 plane; abi minor=6.

## CAPI-21: annotation font load (S2)
`visiaengine_load_font(ve, const uint8_t *data, size_t len)`: **replacement-style** font load/update (TTF/OTF full-form bytes; host injection = the only source, **no default font**, the settled ruling that the 15 MB-class CJK full form cannot be embedded). ## CAPI-40: set_raster_view (R band)
`visiaengine_set_raster_view(ve, min_x, min_y, max_x, max_y) -> i32`: the raster layer's viewport bbox (3857 meters; the finite/min<max domain gate precedes dereference). Return = number of **mounted** tiles inside this viewport (discovery-style scanning semantics: never fabricates unmounted tiles). v1 honest domain: the camera re-centers to the requested bbox, the quad set is unchanged (batches built once at mount time — the fork from load_mvt_dir's ensure loading semantics is recorded in the clause note). Not mounted = rejected.


Band T revision (2026-10-08): the engine keeps **one layer per kind** — mounting this kind again replaces that layer and leaves the other kind mounted and addressable; the first mount on a handle is the one that frames the camera (a later mount never moves it).
## CAPI-41: load_env_hdr (I band)
`visiaengine_load_env_hdr(ve, path) -> i32`: reads a .hdr (RGBE equirect) -> `project_sh9` (256×128 layered sampling, linear domain) -> installs the SH-9 coefficients as the global environment. Replaces the WGPU-35 legacy constant ambient (the `env_on` bit = backend state; never loaded = the old path, bit-for-bit). **Demo-grade declaration discipline** (R3 concession narrowed): L1+L2 irradiance + roughness-weighted reflection tint — not PMREM prefilter / BRDF LUT (= a separate L ticket, never bundled with this entry). Negative = error (unreadable / illegal file), error string via TLS. Engine state (Engine.env_sh) persists across frames; pushed to the backend each pass (the view_block's tail segment).

## CAPI-42: set_node_transform (V2.2)
`visiaengine_set_node_transform(ve, entity, m)` / `visiaengine_get_node_transform(ve, entity, out)`: node **local** rigid transform write/read (column-major f64×16, same shape as GLTF-08). Write = an engine-state override (DrawItem.transform), read = the current value returned (the host struct_size pre-check pattern does not apply — fixed 16 slots, the len domain lives on the wasm bridge side). Domain gate: NULL / non-finite (all 16 elements one by one) / unknown configuration -> negative. Parent-chain composition happens at draw time (world = P·local chain row) — this entry carries **node-local** semantics, not the world matrix. Regression guarantee for existing consumers: non-glTF load paths keep transform at IDENTITY (geo/add_mesh), glTF loads = node-local TRS pass-through (**legacy fix registered**: previously the glTF entity.world hierarchy matrices were discarded at mount — multi-node hierarchies had never rendered correctly, root-fixed in this band). Skinning/vertex animation = the V2.4 domain (this entry governs rigid bodies only).

## CAPI-43: get_node_transform (V2.2)
`visiaengine_get_node_transform(ve, entity, out)`: node-local transform read-back (the symmetric read surface of CAPI-42; fixed 16-slot output, NULL rejected). Unknown configuration = negative. Shares the test body with CAPI-42 (ffi_spec node_transform_write_read domain: write->read round-trip + non-fiducial default identity + NULL/domain gates).
