# visiaengine-render-wgpu behavioral contract (SDD)

> Clause format: `## WGPU-NN: name`. Bidirectional traceability: `scripts/spec-trace.sh`.

## WGPU-01: instance_create_headless
`create_instance()` constructs the wgpu Instance with `Backends::PRIMARY`: passing means no panic and no DISPLAY/surface dependency (on a machine without a GPU the construction itself is still legal).

## WGPU-02: adapter_enumeration_typed
`available_adapters()` returns the typed surface `Vec<wgpu::AdapterInfo>`: an empty vec is legal when no adapter exists, a panic is illegal (a missing driver is a reportable state, not a crash reason).

## WGPU-03: golden_center_pixel
`render_offscreen_triangle()` (640×480 RGBA8) center pixel is red (R≥200, G/B≤60, A=255, tolerance 16); when no adapter is available it prints SKIP and returns legally (the verification-site obligation is recorded by the caller).

## WGPU-04: golden_frame_dimensions
The returned frame's `rgba.len()` is exactly `width*height*4` (the 256-aligned row pitch is guaranteed by the size choice, 640 satisfies it naturally).

## WGPU-05: golden_corner_clear_color
The four corner pixels equal the clear color (13,18,26)±16 — the counter-evidence against full-screen pollution.

## L2 window smoke (narrative clause, **no number, excluded from the bidirectional grep**)

`examples/clear.rs` accepts `--frames N` for automatic exit; CI runs `xvfb-run -a pixi run smoke-clear`
(N=3) asserting exit 0 = the full winit->surface->frame-loop chain passes E2E.
Without a local DISPLAY this layer is verified only in CI.

## WGPU-06: golden_cube_center_hit
`render_offscreen_cube()` (procedural 8-vertex cube MeshDesc, zero asset dependency) center pixel red-dominant (r≥g+40 and r≥b+40) — shading, not the clear.

## WGPU-07: golden_cube_corner_clear_color
Four corners = clear color ±16 (the counter-evidence that the cube does not pollute the full frame).

## WGPU-08: golden_cube_silhouette_row
Midline row, non-clear segments: exactly 2 clear↔painted transitions on the left/right plus a continuous segment wider than 100px (dimensional correctness of the orthographic front projection).

## WGPU-09: material_uniform_path_live
The same offscreen pipeline with a changed material (green) -> center pixel green-dominant (live evidence of the uniform binding path, not a SKIP false-green).

## WGPU-10: golden_far_origin_pixel_identity
`render_offscreen_cube_at(offset)`: cube local mesh + origin=(1e7,0,0) + camera following at 10m — center-red/four-corners-clear **pixel-identical** to the origin=0 version (the end-to-end proof of D7 rebase on the real pipeline; SKIP when no adapter).

## WGPU-11: golden_geo_fill_hit
park.geojson full chain (parse -> tessellate -> D7 upload -> orthographic bird's-eye offscreen): the pixel neighborhood of buildingB's projected barycenter hits the default blue fill — the existence proof of the geo × pipeline merge (SKIP when no adapter).

## WGPU-13: depth occlusion correctness
The mesh pipeline attaches a Depth32Float surface (pipeline `Less` + write on; pass clears 1.0 per frame / store Discard; size-driven rebuild of the MeshCore internal caches): in a multi-entity scene **near-side coverage is independent of draw order** (the picked part and the rendered-visible part agree — the WGPU-12 two-box stacking assertion locks the behavior). The window/surface path shares the same depth configuration as headless (`render_view` size-parameterized).

## WGPU-12: selection highlight rendering plane
The pick chain closes into something renderable: screen ray (REND-21/22) -> `pick_meshes` (REND-23/24) -> the selected entity's material rebuilt with the highlight pure color (**CPU-side overwrite, the rendering-side minimal subset of [E3D:A5] by-name**) -> center-pixel = highlight color-family assertion (two-box stacking scene, pick_highlight.rs). The selection state itself = host/example-layer `Option<EntityId>` data (the engine adds zero state).

## WGPU-14: Textured pipeline sampling chain
Material binding 32B block `[base_color, repeat, specular, pad]` (**value-domain contract CORE-16**: base_color host plane = sRGB/CSS convention, the backend converts to linear before writing the uniform — the whole lighting chain runs in linear domain, the srgb target store hardware-encodes back to the perceptual domain) (binding2 shares layout and size with Flat — the Flat-side shader ignores the trailing fields = the construction guarantee of per-pixel zero regression [Momus-B1]). The textured variant (independent bgl/pipeline, the mega-bool branch rejected [E3D:B2]): fragment `out = base·shade ⊗ texel.rgb`, `a = base.a·texel.a`; uv vertex attribute @location(2) (missing = zero-filled, samples texel(0,0) everywhere). `upload_texture`: RGBA8 (**bytes = sRGB-encoded**, the Rgba8UnormSrgb format = sampling-side hardware decode [CORE-16]), rows zero-padded to 256B (the write_texture constraint), zero size / data shorter than w·h·4 -> Err; material referencing an unknown texture id -> Err (no silent downgrade to Flat). specular mock-up [4ab①]: ~~participates in the existing Lambert brightness coefficient~~ **retired by N6/WGPU-35** — real PBR has landed (GGX used directly, the `specular` IR field is retained but never consumed by shaders; the io-layer glTF roughness_factor/metallic_factor pass through, the inversion mapping retired); block layout 32B->48B see WGPU-35/REND-45.

## WGPU-15: repeat = sampling phase multiplier

## WGPU-18: Points splat pipeline (4de)

## WGPU-20: PCSS three stages (4f)

Unoccluded objects = judged lit (early exit ③); outside the light cone = judged lit (no cascades [not-built④]). **Monotonicity contract**: light angular size size↑ -> the ground penumbra mid-gray strictly >2× (both-sided lock: near-hard shadow <400px and bounded <6000px).

## WGPU-21: clipping pipeline, mesh family (B2)

## WGPU-26: multi-viewport split-screen pipeline (⑤b)
`render_view_rects(passes: &[(Frame, ViewportRect)], view, w, h, fmt, policy)`: on a single surface with **a single full-size depth** (key = surface size, the rect does not participate in the key — same-size viewports cost zero rebuilds) N scissor-fenced passes, each carrying its own Frame (camera/px_world_scale autonomous, commands and resource tables shared). **Clear semantics settled on this machine (adjudication gate measured 2026-09-18)**: wgpu30 `LoadOp::Clear` acts on **the entire attachment** (under the AllClear form the later region swallows the earlier = current behavior; consistent with the Vulkan render-area conclusion) ⇒ **the safe form = first pass Clear (full-size background color, incidentally supplying the gap color) + subsequent passes Load**, the only publicly documented form (`MultiClearPolicy::AllClear` is probe/teaching-only). depth: **every pass must Clear(1.0)+Discard** — the first pass's full-size clear already covers the whole area, and a later Load would take the main view's opaque-ground depth and swallow the small picture's occlusion wholesale (caught by the 2026-09-18 pixel gate, still current); no consumer of depth between passes, so Store bandwidth is saved; the **scissor-fenced rasterization** makes cross-region depth mutually invisible (color/depth write fence, shared depth with zero crosstalk = gate ③ lock). The caster pre-pass runs **once** (frame0 configuration; light-space math is independent of the main camera -> the double projection shares the shadow map [adjudication d], gate ④ double-region shadow current lock). **Canary discipline**: `ViewportRect::full` or a rect equal to full **emits no set_viewport/set_scissor call** (default full frame = the old path **byte-equal**, gate ② lock); the `render_view_format` old entry is untouched. Single clear color master = the first Frame's ClearColor (later Frames' ClearColor is not consumed, the same shape as the find_map law).

## WGPU-33: EDL point-cloud post-process (eye-dome lighting)
`Frame +{ edl: Option<EdlSetup> }`: `None` = off with **bitwise zero regression** (the old direct-render path untouched — no extra pass, depth still Discard, no intermediate resources built; canary = edl.rs double-render byte-equality + the OFF-after-ON round trip equal); `Some(EdlSetup{strength})` = point-cloud silhouette legibility post-process, `EdlSetup::new` rejects non-finite/≤0 (None = explicit reject). **Pipeline orchestration**: the main pass renders into a **size+format cached** intermediate color surface (RENDER_ATTACHMENT|TEXTURE_BINDING; the swapchain view lacks TEXTURE_BINDING, hence the mediation is mandatory), depth Store to feed EDL consumption; then the EDL fullscreen pass (TriangleStrip draw(0..4), edl.wgsl vs_main/fs_main) samples the intermediate color + main depth and writes the final view (color Load+Store). **Pass state = color-only**: wgpu 30 usage-scope law (sampling depth = RESOURCE while DEPTH_STENCIL_WRITE in the same pass are mutually exclusive) ⇒ depth is read only via textureLoad, the pass drops the depth attachment (pipeline depth_stencil=None, the main pass already Stored). Darkening predicate: `rel=|depth_avg−depth_center|/(1−depth_center)` (a **scene-scale-invariant ratio** — an absolute threshold varies brittlely with near/far [PIT-8], probe-measured intrinsic ≈3e-4 / edges ≈2e-3..5e-3, readings after decoding the sRGB output); `k=clamp(rel·strength·3,0,0.7)` capped; background (depth≥0.999) never darkened (no halo). `strength` semantics = an f32 over 0..∞, the E204 `--edl` setting = 0.35 (probe-pinned). **The multi-viewport path (render_view_rects) ignores the `edl` slot in this band** (WGPU-26 semantics unchanged, ticket trigger = a multi-viewport point-cloud demo).

## WGPU-34: post pass chain orchestration (N4)
`Frame.post` non-empty => the main pass renders into a **stage color intermediate** (`ensure_stage_color(i,w,h,fmt)` size+format cached, fixed 2 slots; when EDL is on the EDL intermediate doubles as the chain input) + depth Store (single flag `edl_on || post_on`); then one fullscreen pass per effect (TriangleStrip draw(0..4), bloom.wgsl/outline.wgsl vs_main same shape as edl.wgsl): **effect i reads stage[i-1] (or the chain input) and writes stage[i]; the LAST effect writes the final view** — the final view is never sampled (wgpu usage-scope law: RESOURCE+COLOR_TARGET conflict within one pass; cross-pass sampling is legal [PIT-33 scope rule]). bgl = EDL's 4-binding shape (color/depth/sampler/params UBO — bloom ignores depth but binds it for shape sharing; sampler = edl_smp reuse, nearest-clamp); pipelines are per-(effect,format) lazy (edl_pipeline same pattern); params=(texel_w, texel_h, strength/width, width_texels). **Zero-effect byte law**: post empty AND edl None => legacy direct path byte-identical (no extra pass, depth Discard, zero new resources; canary = post_chain.rs double-render bitwise equality + OFF-after-ON round trip). bloom = 9-tap neighborhood luma threshold + additive composite (THRESHOLD=0.25 probe-pinned); outline = depth-neighborhood gradient ratio (WGPU-33 rel formula family, threshold 0.08) + selection-orange mix; background (depth>=0.999) is never outlined. Multiview path (render_view_rects) ignores the post slot this band (EDL-style debug_assert loud). Test anchors: post_chain.rs four gates (off bitwise / bloom / outline / chain-order determinism).

## WGPU-35: GGX PBR material block v2 (N6)
Material uniform block **32B->48B** (REND-45 layout: base_color@0(16) / repeat@16(8) / roughness@24 / metallic@28 / 16B tail padding — addresses fixed by the WGSL vec4/vec2 alignment law; the retired mock `specular` float slot is absorbed by the tail padding, the IR field kept but never consumed by shaders = the WGPU-14 note closed). mesh.wgsl's two lighting sites (vs and vs_inst, all variants consume the same block = single source of truth [Momus-B1 form]) replace the mock `0.35+0.65·ndl+specular·ndl` with **Cook-Torrance GGX**:
- **D** (GGX/Trowbridge-Reitz): `alpha = max(roughness²,1e-4)`; `D = alpha²/(π·(ndh²·(alpha²−1)+1)²)`
- **G** (Smith-Schlick): `k = alpha/2`; `G = G1(ndv)·G1(ndl)`, `G1(x) = x/(x·(1−k)+k)`
- **F** (Schlick): `F0 = mix(vec3(0.04), albedo, metallic)`; `F = F0 + (1−F0)·(1−vdh)⁵` (`1−vdh` clamped to [0,1] first — negative pow base = NaN, hard prevention)
- spec = `D·G·F/(4·ndv·ndl+eps)`; diffuse = `albedo·(1−metallic)·(1−F)·ndl`; final = `(diffuse+spec)·light_intensity + ambient`
- **IBL-lite ambient** (a constant radiance term, the IBL family = uniform constant environment): `ambient = vec3(0.35)·albedo·(1−roughness·0.5)`. The 0.35 constant = probe-pinned (PIT-8): the legacy dielectric (roughness=1/metallic=0) lands in the old brightness band (measured ground 177 vs the old 187 family — the E501/shadows family all-green self-proves), the probe note entered in the ledger. light_intensity = `length(light.rgb)` (the view block sp.a reused, the vector doubling as brightness).
- vs_inst: the instance color folds into albedo (the multiply chain preserved); back-lit faces (ndl≤0) = ambient-only (physically correct — bloom food-group back-lit faces no longer exceed the threshold, the E507/post_chain scene side already adapted to normals facing the light).
Test anchors: the E508 example (metallic/dielectric differential + roughness ladder peak/diffusion probe-pinned values) + the shadows/transparency/post_chain/property_golden/capi render_spec re-probe band (ledger in the clause-body notes).

## WGPU-36: SSAO depth-only ambient occlusion (N7)

The zero-effect law unchanged (post empty = old path bitwise, post_off_bitwise untouched). Test anchors: post_chain.rs `post_ssao_differs` (off-vs-on differential probe-pinned 3862px @128² + determinism) + the contract_spec domain-reject gate; the E509 example (keys 1/2/3/0 + title echo + the `--frames` off-vs-on 18678px @320² assertion + off determinism).

## WGPU-38: Screen-space depth haze post effect (W band)

## WGPU-39: SH-9 environment irradiance (I band)
View block 256B->384B (the bit order of floats 0..64 unchanged = the existing-construction guarantee persists; tail env_sh 27 floats@64..91 + env_on flag@91 + pad). `set_env_sh(sh)` engine-level state; all-zero / flag 0 = the legacy constant-ambient bitwise regression path. Honesty note: directional ambient + roughness-attenuated reflection — no angular-resolution specular (the missing cubemap sampling is dictated by the low-frequency nature of SH, stated explicitly in the clause).
